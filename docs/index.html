¿Qué es y para qué sirve?

El conector IBM QRadar permite que el agente de Ruvic consulte y gestione ofensas de seguridad en tu consola de QRadar — listar ofensas, ver su detalle completo, y actualizar su estado.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Qué ofensas abiertas hay?"
  • "Dame el detalle de la ofensa #123."
  • "Cierra la ofensa #123, ya fue atendida."

Operaciones soportadas:

OperaciónQué hace
cybersecurity.list_offensesLista ofensas, con filtro por estado
cybersecurity.get_offense_detailConsulta el detalle completo de una ofensa
cybersecurity.update_offense_statusActualiza el estado de una ofensa (Open/Hidden/Closed)
QRadar es siempre on-premise A diferencia de otros conectores en la nube, QRadar no tiene un endpoint compartido — cada cliente tiene su propia consola, con su propia URL.

Prerrequisitos

  • Una consola de IBM QRadar accesible por red desde donde corre Ruvic.
  • Acceso de administrador a QRadar para crear un Authorized Service (SEC token).

Configuración en el fabricante

  1. Ve a Authorized Services. En QRadar: Admin → User Management → Authorized Services.
  2. Crea un nuevo servicio autorizado. Clic en "Add Authorized Service", nombre descriptivo (ej. "Ruvic QRadar Connector").
  3. Elige el User Role y Security Profile. El User Role debe tener capacidad "Offenses" habilitada; el Security Profile debe acotarse a los dominios/redes que el agente necesita ver — evita usar "Admin" completo.
  4. Define la expiración y copia el token. Pon una fecha de expiración (recomendado), genera el servicio, y copia el "Authentication Token" — es tu SEC token.
  5. Despliega los cambios. Vuelve a la página de Admin y haz clic en "Deploy Changes" para activar el servicio.

Permisos requeridos

PermisoPara qué lo usa el conector
Capacidad "Offenses" en el User RoleNecesario para las 3 operaciones

No uses el rol "Admin" completo — acota el Security Profile a los dominios/redes relevantes.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta IBM QRadar y pulsa Configurar.

Completa la URL de la consola y el SEC Token. Deja la versión de la API y el timeout en sus valores por defecto salvo necesidad específica.

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a [URL de la consola]".

  2. Prueba mínima con el agente.

    Pide algo de solo lectura primero:

    "¿Qué ofensas abiertas hay?"

Solución de problemas

Mensaje / síntomaCausa probable y solución
"SEC token inválido o permisos insuficientes"El token expiró, fue revocado, o el User Role no tiene la capacidad "Offenses" habilitada.
Error de certificado TLSMuchas instalaciones de QRadar usan certificados autofirmados — considera desactivar "Verificar SSL" solo si confías en la red.
"No se pudo conectar..." (timeout/red)Verifica que la consola sea alcanzable desde donde corre Ruvic — puede requerir VPN o whitelist de IP.

Preguntas frecuentes y notas de seguridad

¿El agente puede eliminar ofensas?

No. Solo puede listar, consultar detalle, y cambiar el estado (Open/Hidden/Closed) de ofensas existentes.

¿Dónde queda guardado el SEC token?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

¿Qué hago si el token se compromete?

Ve a Admin → Authorized Services en QRadar, elimina el servicio comprometido, crea uno nuevo, y actualiza el token en el formulario del conector.

Buenas prácticas Usa un Security Profile acotado, no "Admin"; ponle fecha de expiración al SEC token; y confirma la intención del usuario antes de cerrar/ocultar una ofensa real.
